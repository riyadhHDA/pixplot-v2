Exploring large art history collections on one PC

PixPlot v2 rewrites the idea behind Yale's PixPlot with current vision models. It arranges tens of thousands of artworks on an interactive map, searches for shared compositions or recurring details, and keeps track of which model and metadata source produced every result.

Division of work

A vision model groups images from their pixels. It knows nothing about patronage, workshops or actual influence, so the workflow keeps each role separate.

PixPlot

Computes neighbourhoods, indexes image regions and builds the maps.

Assistant (MCP)

Queries the corpus, assembles comparison plates and suggests leads.

Art historian

Looks at the works, checks the sources and decides what holds up.

All of WikiArt on a single machine

The full dataset (80,716 works, 33.7 GB) was processed end to end on a Windows 11 desktop with an AMD Radeon RX 7900 GRE and 16 GB of RAM: ingestion, DINOv3 and SigLIP 2 vectors, an index of 1.58 million regions, clustering, maps and a blind audit.

Four ways of comparing

Instead of merging everything into a single score, PixPlot keeps four separate spaces. When two paintings sit close together in one space and far apart in another, that gap is often more revealing than the score itself.

DINOv3

Form

Silhouettes, framing, layout and visual motifs.

Same composition?

SigLIP 2

Subject

What can be put into words: theme, genre, school, iconography.

Same subject?

CIELAB

Colour

Proportions of hues, lightness and saturation.

Same palette?

DINOv3, layer 6

Touch

Grain, hatching and brushwork, regardless of the subject.

Same handling?

A fifth way, on trial: posture

It finds the figures, estimates their skeletons and compares the poses, mirror images included. Without any label, it finds gestural formulas across centuries (Aby Warburg's Pathosformeln): 25 of the 37 "same gesture" pairs it proposed were validated on review. It does not beat form over all the pairs and only sees works where a figure is detected (48 %), so it stays apart, marked "trial". A similar pose is a lead, not proof that one artist saw the other.

What the Atlas does

A local web interface in plain JavaScript (deck.gl) that works offline.

Search by text, region or detail

Filter by metadata, search with free text in French or English, look up described details ("a halo", "a skull") or draw a box directly on a painting.

Compare and inspect why

Put up to six works side by side with scores across all spaces, highlight matching zones with the "Pourquoi ?" button, and inspect neural-free visual measures (balance, symmetry, chromatic entropy).

Maps, dates, places and concepts

One map per space, a timeline, a geographic view with typed places (after ARTL@S) and 2D conceptual axes from any two words (after 2D CLIP).

Flag doubtful labels

Works contradicted by all their neighbours are collected in a separate list. Some turn out to be cataloguing mistakes, others genuinely unusual paintings.

Import museum collections (IIIF)

Reads IIIF v2/v3 manifests and collections with normalised metadata and rights. Tested on the Yale Center for British Art.

MCP server (20 tools)

Connects Claude or another MCP-compatible assistant so it can search, view images and crops, run visual measures and save notes in the shared notebook.

Learned notions

An autoencoder breaks the "subject" and "form" spaces into about 2,000 notions each: objects, motifs, layouts the catalogue does not index. Each is named with Iconclass when the name is reliable, and its works light up on the map.

Duplicates and variants

Works entered twice, and replicas, series, print states or copies, with the labels that contradict each other from one entry to the next.

Combined filters

Style, genre, artist, group, date and atypicality at once, with the count each choice would give; the selection goes to the notebook or into a Research Pack.

Every computation is saved in a dated run folder with its model and parameters. Exporting creates a Research Pack (.zip) with the images, sourced metadata and scores so a search can be archived or shared.

Some measurements on WikiArt

Across 80,716 works, share of the 10 nearest neighbours that carry the same label as the query work.

Form (DINOv3)50.8%52.4%76.8%21%20%
Subject (SigLIP 2)61.6%62.0%79.5%44%26%
Touch53.0%49.6%62.8%62%30%

SigLIP 2 recovers standard categories best (artist, style, genre), largely because it has learnt art-historical vocabulary from web captions.

DINOv3's middle layer catches brushwork styles: Pointillism jumps from 21% to 62%, and the artist's hand comes through better than with the global vector.

Close copies show up at rank 1 (Raphael after Perugino, Van Gogh after Millet, Manet after Goya), but once an artist heavily transforms a model (Picasso after El Greco), none of the current spaces follows.

WikiArt labels are noisy: the blind audit turns up genuine cataloguing errors (religious scenes tagged as genre paintings). HDBSCAN also fails to scale on such a dense continuum.

All 80,716 works in one view

The full map shows 142 coloured groups. Zooming in streams higher-resolution thumbnails on the fly, and clicking any painting opens its record.

Progress

Working rule: test before keeping. A new model only stays if it beats what is already there on a benchmark; failed attempts (TIPSv2, PE-Spatial, HDBSCAN) are documented and dropped.

  1. 0.1–0.12

    Core pipeline, spaces, disagreements and pair benchmark

    Ingestion, four spaces, Atlas, text and detail search, MCP server, IIIF, nested Leiden communities, Disagreements panel and 104 hand-reviewed reference pairs.

  2. 0.13

    Described zones, critical layer and ARTL@S places

    TIPSv2 tested on RichArt and dropped in favour of a 1.6M SigLIP 2 region index; model bias cards, corpus audit and typed/dated places.

  3. 0.14

    Iconclass group naming

    The small hand-written lexicon replaced with CC0 Iconclass terms and verifiable codes; reviewed on 83 groups: Iconclass more accurate 39 times, the old name 24 times (released in 0.18).

  4. 0.15–0.16

    Composition, "Why?", conceptual axes and visual measures

    PE-Spatial benchmarked on composition pairs and dropped (DINOv3 stays ahead); zone matching in the comparator, 2D conceptual axes and neural-free visual measures (Stork).

  5. 0.17–0.20

    Filters, duplicates, titles and emotions

    Combined filters, duplicates and variants (SSCD), titles, dates and artists recovered for 70,902 WikiArt works (MMArt), viewers' emotions (ArtEmis), order of the paint surface; SSCD, Depth Anything, LocalMAP, PE-Core and CSD measured and dropped.

  6. 0.21

    Posture, learned notions, "Why?" put to the test

    "Posture" space evaluated, learned notions of the "subject" space, confidence intervals for the pair benchmark; the "Why?" button first fails the occlusion test, then passes it once fixed.

  7. 1.0

    Towards 1.0

    Stable, documented commands and file formats (done, checked by tests), at least 100 validated pairs (done), complete documentation in both languages (done), installation tested on a fresh machine (to be done last).

Install and try it

Requires Python 3.12. A GPU speeds up extraction considerably (AMD ROCm on Windows, or CUDA), though everything also runs on CPU for testing a small folder. See INSTALL_GPU.md.

# install
python -m venv .venv
.venv\Scripts\activate                 # Linux / macOS: source .venv/bin/activate
pip install -e ".[dev,ml]"

# process a folder of images
pixplot ingest "D:/MyImages"           # catalogue, thumbnails, duplicates
pixplot import-metadata meta.csv       # artist, date, style… ("path" column required)
pixplot embed                          # DINOv3 vectors (GPU), resumable
pixplot analyze                        # groups, UMAP map, neighbourhoods
pixplot serve --open                   # opens the Atlas at http://127.0.0.1:8765

To run the full pipeline in one command: bash scripts/full_pipeline.sh data/my_corpus "My source". Everything stays local; nothing is uploaded anywhere.
